## What does extracting an HTML table to CSV do?

Copying a table out of a web page usually leaves you with either an image or
a pile of unaligned text. This tool parses real HTML, finds every
`<table>` element, and converts the one you pick — by 0-based index — into
CSV, expanding any `colspan` so the columns stay aligned and turning `<br>`
tags into real line breaks inside a cell.

## How it works

1. The HTML is parsed with the browser's own HTML parser, so malformed
   markup is handled the same way a browser would render it.
2. Every `<table>` in the document is collected; **table index (0-based)**
   picks which one to convert (negative indexes count from the end, so
   `-1` is the last table). Rows belonging to a nested table are excluded
   from their parent's rows.
3. Each `<td>`/`<th>` becomes one cell. A `<br>` becomes a newline inside
   that cell; other whitespace collapses to single spaces, matching how a
   browser renders the text.
4. A `colspan="n"` on a cell repeats its text across all `n` columns it
   covers, so a spanning header still lines up with the columns below it.
5. Cells are quoted under RFC 4180 rules and joined with your chosen
   **delimiter**; rows are padded to the widest row.

```example
title: a simple table with a header row
input: <table><tr><th>Name</th><th>Age</th></tr><tr><td>Ada</td><td>36</td></tr><tr><td>Grace</td><td>85</td></tr></table>
output: Name,Age
Ada,36
Grace,85
```

```example
title: a custom delimiter and a quoted cell
params: {"delimiter": ";"}
input: <table><tr><td>a;b</td><td>c</td></tr></table>
output: "a;b";c
```

A `colspan` cell fills every column it covers, keeping the rows below it
aligned:

```example
title: colspan expands across the columns it covers
input: <table><tr><td colspan="2">span</td><td>x</td></tr><tr><td>1</td><td>2</td><td>3</td></tr></table>
output: span,span,x
1,2,3
```

`<br>` and self-closing `<br />` both become a real newline inside the CSV
cell, which is quoted to keep the line break intact:

```example
title: <br> becomes a newline inside a cell
input: <table><tr><td>a<br>b</td><td>c<br />d</td></tr></table>
output: "a
b","c
d"
```

## Options

- **table index (0-based)** — which `<table>` in the document to convert,
  default `0` (the first). Negative values count from the end.
- **delimiter** — the field separator, default `,`. Accepts an escape
  (`\t`) or a literal character; a backslash-escaped delimiter such as
  `\|` is unescaped to a literal pipe rather than used verbatim.

## Common uses

- Pulling a data table out of a saved web page or a scraped HTML fragment.
- Converting a table copied from documentation or a wiki export into a
  format a spreadsheet can open.
- Recovering CSV from a table that was originally generated by
  [csv to html table](/util/csv_to_html/) — the two tools use the same
  `<br>` convention, so line breaks inside cells survive the round trip
  (runs of spaces and leading or trailing whitespace in a cell do not).

## Tips and pitfalls

- HTML entities are decoded automatically (`&amp;` becomes `&`), and
  non-ASCII and astral characters such as emoji survive intact.
- An input with no `<table>` element at all throws an error rather than
  returning empty output, so a typo in your HTML is easy to notice.
- An out-of-range **table index** throws, naming how many tables were
  actually found.
- Nested tables are handled correctly: a `<table>` inside a cell of another
  table is its own separate table for indexing purposes and does not add
  rows to its parent (its text still appears inside the containing cell).
- `rowspan` is not expanded: a cell that spans several rows appears only in
  its first row, so the cells of the rows below it shift left.

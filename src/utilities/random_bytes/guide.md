## What is a random bytes generator?

Many things in software need raw random bytes rather than a random-looking string: an encryption key, a session token, a cryptographic nonce, or test data for a binary protocol. This tool is the equivalent of piping `/dev/urandom` through `head -c N`, or running `openssl rand`, except it stays in the browser and lets you view the same bytes in whichever text encoding you actually need next.

## How it works

Ask for a number of bytes and a format, and — with the seed left at its default of `0` — the tool draws that many bytes from the browser's cryptographic random number generator and renders them. The examples on this page set a seed so their output stays fixed:

```example
title: bytes as hex (seeded for a reproducible example)
input:
params: {"count": 8, "output": "hex", "seed": 42}
output: 9972daab2c86459f
```

The same seed yields the same byte stream, so the first four of those bytes come out again as a ready-to-paste C array:

```example
title: the same bytes as a C array
input:
params: {"count": 4, "output": "c-array", "seed": 42}
output: uint8_t data[4] = { 0x99, 0x72, 0xda, 0xab };
```

Base64url output replaces the `+`/`/` characters with `-`/`_` and drops the `=` padding, which make standard base64 awkward inside URLs or filenames:

```example
title: bytes as base64url
input:
params: {"count": 4, "output": "base64url", "seed": 1}
output: oACH-w
```

Decimal output lists each byte's plain 0–255 value, space-separated — useful for reading values off by eye or pasting into a language without a convenient hex parser:

```example
title: bytes as decimal values
input:
params: {"count": 4, "output": "decimal", "seed": 1}
output: 160 0 135 251
```

Asking for zero bytes returns an empty result in every format rather than an error:

```example
title: a count of zero
input:
params: {"count": 0, "output": "hex"}
output:
```

## Options

- **count** — how many bytes to generate; default `16`, from 0 up to 1,048,576 (1 MiB). Larger requests are drawn in 64 KiB chunks internally, since the browser's `crypto.getRandomValues` refuses to fill more than that in a single call.
- **output** — `hex` (default), `base64`, `base64url`, `decimal`, `c-array`, or `bytes` (the raw byte value itself, for piping into another step in a pipeline rather than reading as text).
- **seed (0 = crypto random)** — `0` (the default) draws real randomness from the browser's CSPRNG (`crypto.getRandomValues`) on every run. Any other integer instead feeds a small, fast, non-cryptographic PRNG (mulberry32) that reproduces the exact same byte sequence every time, which is useful for tests and documentation but must never be used to generate an actual key, token, or nonce.

## Common uses

- Generating a symmetric encryption key or an HMAC secret of a specific byte length.
- Generating a nonce or initialization vector for a cipher that requires one.
- Producing raw test fixtures for binary protocols or file formats, in whichever encoding the receiving tool expects.

## Tips and pitfalls

- This tool ignores its input entirely — the input box has no effect on the generated bytes.
- The same non-zero seed always produces the same byte stream, and a larger count simply extends it — the first bytes stay the same — letting you check that two systems parse the same input the same way.
- For a printable random string built from a specific character set rather than raw bytes, use [random string](/util/random_string/) instead.
- To turn these bytes into something else — a hash, an HMAC, or a hex dump — chain a step such as [hash](/util/hash/), [hmac](/util/hmac/), or [hex encode](/util/hex_encode/) after this one.
